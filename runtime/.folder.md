# Runtime manifests

- `release-manifest.json`: Runtime-owned `ink-claude-cli-envelope/v1` diagnostic contract.
- `capabilities.json`: detailed delegated/enforced capability and evidence matrix for Dream's locked CLI `2.1.241` and `ink-claude-dream-agent-sdk==0.2.145`.
- `platforms.json`: external official `2.1.241` Linux package pins.
- `artifact-manifest.json`: user-supplied, external, unmodified official artifact and redistribution gate.
- `entrypoint-policy.json`: wrapper/child boundary, management commands, authentication preservation, and no-injection policy.
- `runtime-data-contract.json`: workspace/TMPDIR/transcript/MCP/plugin/auth ownership and lifecycle.
- `bare-profile.json`: explicit caller-supplied `--bare` carrier requirements and production blocker.
- `dependency-licenses.json`: build dependency licenses, local-core ripgrep/seccomp runtime assets, and the official legal/publish decision.
- `cleanroom-artifact-policy.json`: restored-source-free MIT Runtime boundary, Dream's 14 required capabilities (including stable `sandbox.notion-cli`), prohibited inputs, target qualification basis, and digest-bound Dream real-business/publication evidence gate. It is the capability source-of-truth for generated clean-room npm manifests.
- `attestations/`: public, privacy-redacted release receipts. Raw accounts, logs, database rows, OAuth material, callbacks, and transcripts are forbidden.
- `cleanroom-npm-policy.json`: exact `package/` selector source root and `cli.js` entrypoint, Bun cross-compile target, five scoped package identities, private platform executable paths, release/capability manifests, native magic, checksum, CycloneDX SBOM, license, mutable-data, and zero-source-map requirements.
- `cleanroom-sandbox-policy.json`: exact Apache-2.0 Sandbox Runtime pin, four supported targets, Workspace/tmpdir/network/environment/process bounds, validated Notion home/native `ntn`/host projection, subprocess exclusions, and the no-raw-process fallback rule.
- `cleanroom-dependency-licenses.json`: exact dependency/license/file inventory for every third-party package reachable from the clean-room CLI bundle; packaging turns it into a checked report and third-party notices.
- `pruning-decision.json`: executable fail-closed core-pruning decision, candidate evidence, and authorization/build inputs required before any vendor-core deletion.
- `core-prune-profile.json`: Bun `1.4.0` local build profile, retained Dream capabilities (including synchronous Agent/Task, MCP management, sandbox, and image roots), authorized package-asset manifest, the Linux Docker-style `apply-seccomp` passthrough plus `sandbox-runtime@0.0.45` BPF asset at the restored 2.1.88 path, disabled feature set, defines, and suffix/prefix/output DCE assertions.
- `core-resolution-map.json`: deterministic exact/prefix bare-specifier and digest-bound facade mapping for explicitly supplied external source/package trees, including the narrow MCP management entry and importer-aware `signal-exit` API split; unresolved entries fail and remain local evidence.
- `local-artifact-policy.json` / `local-release-manifest.json`: production-qualified local package identity plus the separately installed `ink-claude-code-bun-1.4.0` toolchain contract; the Runtime artifact does not bundle or overwrite ambient Bun.
- `npm-release-policy.json`: `@glide-the` selector/platform package names, four native targets, exact `bun@1.4.0`, ripgrep checksums, source-map/user-data exclusions, Windows/musl refusal, and Trusted Publishing identity. It references but never overrides the closed local legal policy.
- `seccomp/`: repository-authored Linux local-core helper and its folder contract. The 2.1.88 passthrough drops the leading BPF argument before `exec`; it is never a public clean-room npm input.

The legacy official-envelope and local-core capability files describe different artifacts; they do not acquire `sandbox.notion-cli` merely to mirror the clean-room Runtime. `scripts/package-cleanroom-npm.mjs` maps every clean-room required ID into each generated platform/meta capability manifest, which is the Dream fail-closed evidence path. Historical `0.1.3` and `0.1.5` acceptance receipts remain immutable. Runtime `0.1.4` retains its published qualification evidence. Runtime `0.1.6` changes the selector source/layout, so its production, redistribution, publication, and all four target-qualification values are false until new same-SHA evidence exists; the provider-free fixture cannot open them. Never place a core binary, vendor/restored source, user material, or secret here.
