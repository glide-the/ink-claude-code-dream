# Clean-room sandbox

- `sandbox.ts`: defines the trusted sandbox adapter contract. `FailClosedSandbox` is the production default when no isolation backend is installed.
- `production.ts`: binds Bash to the canonical Workspace/tmpdir. At Runtime startup it accepts only exact canonical `{workspace}/.notion-home` mode `0700`, a native executable named `ntn` owned by the current user/root and not group/world writable, an optional nonempty single-line token, and an optional canonical regular `{workspace}/.notion-home/workers.json`. The Bash child receives `NOTION_KEYRING=0`; absent/invalid values are omitted. Only `api.notion.com:443`, `developers.notion.com:443`, and `ntn.dev:443` are allowed, conditional on the complete home/executable validation.
- `process-fixture.ts`: provider-free subprocess fixture for timeout/cancel/cwd contract tests. It is explicitly marked untrusted and is rejected by the tool dispatcher unless a test opts in.

The projection is recomputed at every new or resumed Runtime process and is never session-cached. A missing/foreign Workspace home, an ambient token without that bound home, a script/shim named `ntn`, or a missing native executable disables the Notion carve-out without weakening the base sandbox. A wrong or missing workers path omits only `NOTION_WORKERS_CONFIG_FILE`; it is never copied. The bounded subprocess fixture is not a filesystem or network sandbox.
