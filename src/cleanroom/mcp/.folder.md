# Clean-room MCP client

- `types.ts`: normalized server configuration, registry snapshots, and model-tool contracts.
- `config.ts`: reads repeated `--mcp-config` JSON values or JSON files, validates `mcpServers` without changing server names, and keeps legacy `sse` distinct from Streamable HTTP.
- `naming.ts`: creates deterministic model-facing `mcp__<sanitized-server>__<tool>` names while preserving exact registry keys.
- `registry.ts`: owns official MCP SDK v1 clients, stdio/SSE/Streamable HTTP transports, initialization, discovery, calls, resource reads, lifecycle, and status transitions. Stdio child environments remove the four production-Bash-only Notion variables even if ambient or explicitly repeated in MCP config.
- `management.ts`: exposes `mcp_status`, `mcp_toggle`, `mcp_reconnect`, and the single outer-CLI management wire.
- `management-cli/`: implements Dream-compatible list/get/add/remove/login/logout argv, private user config, projected credentials, and bounded output.
- `builtin-tools.ts`: adapts MCP resource listing and reads to the built-in `ListMcpResourcesTool` and `ReadMcpResourceTool` model-tool shapes.
- `oauth/`: implements private DCR/PKCE persistence and headless begin/callback/refresh/logout operations over the public MCP SDK OAuth API.
- `index.ts`: stable public exports for the clean-room MCP slice.

Only `stdio`, legacy SSE, and Streamable HTTP are supported. SSE uses the official SDK `SSEClientTransport`; `type: sse` requires an absolute HTTP(S) URL and remains a distinct registry type. Remote servers without a matching credential connect anonymously even when a legacy OAuth hint exists. A `401` becomes `needs-auth` only after a Bearer challenge leads to validated RFC 9728 protected-resource and authorization-server metadata; missing advertisement and invalid metadata remain distinct safe failures, including later SSE POST endpoints. Matching projected credentials inject the persistent SDK provider for HTTP and SSE, including configs without an OAuth marker, so refresh rotation survives a Runtime restart. The SDK owns OAuth and bounded `insufficient_scope` reauthorization; the transport adapter only unions the token's prior scope with the challenged scope and maps the SSE transport's missing 403 upscope hook into that same SDK flow. OAuth never opens a browser, and credentials are stored only beneath an explicit canonical `CLAUDE_CONFIG_DIR`. A newer private token wins over a stale Dream projection; refresh rotation is mirrored only after the private commit, while unrecoverable invalidation removes the stale projection. The management CLI mutates only user-scope HTTP definitions and preserves exact server names.
