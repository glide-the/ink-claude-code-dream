# Clean-room MCP client

- `types.ts`: normalized server configuration, registry snapshots, and model-tool contracts.
- `config.ts`: reads repeated `--mcp-config` JSON values or JSON files and validates `mcpServers` without changing server names.
- `naming.ts`: creates deterministic model-facing `mcp__<sanitized-server>__<tool>` names while preserving exact registry keys.
- `registry.ts`: owns official MCP SDK v1 clients, stdio/Streamable HTTP transports, initialization, discovery, calls, resource reads, lifecycle, and status transitions.
- `management.ts`: exposes `mcp_status`, `mcp_toggle`, `mcp_reconnect`, and the single outer-CLI management wire.
- `management-cli/`: implements Dream-compatible list/get/add/remove/login/logout argv, private user config, projected credentials, and bounded output.
- `builtin-tools.ts`: adapts MCP resource listing and reads to the built-in `ListMcpResourcesTool` and `ReadMcpResourceTool` model-tool shapes.
- `oauth/`: implements private DCR/PKCE persistence and headless begin/callback/refresh/logout operations over the public MCP SDK OAuth API.
- `index.ts`: stable public exports for the clean-room MCP slice.

Only `stdio` and Streamable HTTP are supported. Protected HTTP servers require an explicitly injected persistent provider; otherwise they become `needs-auth`. OAuth never opens a browser, and credentials are stored only beneath an explicit canonical `CLAUDE_CONFIG_DIR`. A newer private token wins over a stale Dream projection; refresh rotation is mirrored only after the private commit, while unrecoverable invalidation removes the stale projection. The management CLI mutates only user-scope HTTP definitions and preserves exact server names.
