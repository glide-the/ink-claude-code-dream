# Clean-room MCP management CLI

- `storage.ts`: validates an explicit canonical config root and atomically owns only `.claude.json#mcpServers` and `.credentials.json#mcpOAuth` at modes `0700`/`0600`.
- `argv.ts`: parses the narrow public `mcp list|get|add|remove|login|logout` surface without splitting colon-bearing server names.
- `oauth.ts`: bridges the headless provider to Dream's projected `mcpOAuth` contract, preserves newer private tokens, mirrors token rotation/invalidation atomically, and closes mutation authority before timeout cleanup.
- `index.ts`: renders a one-line-per-server `list`, registry-backed `get` authentication details, Dream-whitelisted failure codes, and the single outer-CLI wire point.

The command never prints config paths, commands, environment values, OAuth tokens, callback URLs, metadata bodies, or persisted document contents. Help is available before any config-root lookup. `add` does not manufacture an OAuth requirement. `get`, proactive `login`, and post-`logout` status reuse real bounded registry classification; successful `list` remains one line per server for Dream parser compatibility. Only user-scoped Streamable HTTP mutation is supported. Unsupported scopes and transports fail closed.
